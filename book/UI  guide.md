# راهنمای تولید رابط کاربری به سبک اپل

هدف: تولید وب‌اپلیکیشن‌هایی که از نظر حس‌وحال، تایپوگرافی، رنگ، فاصله‌گذاری و الگوهای ناوبری، هم‌ارز با اپلیکیشن‌های بومی iOS/iPadOS ساخته‌شده توسط خود اپل باشند — با استفاده از فقط با **HTML + CSS خالص (و در صورت نیاز فریم‌ورک یا کتابخانه UI: bootstrap)**.

---

## ۱. اصول بنیادین (باید در هر تصمیم طراحی رعایت شود)

اپل سیستم طراحی خود (Human Interface Guidelines) را بر سه اصل بنا کرده که هر عنصر تولیدی باید با آن‌ها سنجیده شود:

1. **وضوح (Clarity)** — متن باید در هر اندازه‌ای خوانا باشد، آیکون‌ها دقیق و بدون ابهام، فاصله‌های سفید کارکردی نه تزئینی.
2. **تبعیت از محتوا (Deference)** — رابط کاربری هرگز نباید با محتوا رقابت کند؛ کروم (نوار ابزار، ناوبری) باید عقب بنشیند و محتوا در مرکز توجه باشد.
3. **عمق (Depth)** — لایه‌بندی بصری و حرکت (motion) برای انتقال سلسله‌مراتب استفاده می‌شود، نه صرفاً تزئین.

عامل باید قبل از افزودن هر افکت بصری (سایه، بلور، انیمیشن) از خودش بپرسد: «آیا این به وضوح محتوا کمک می‌کند یا صرفاً تزئین اضافه است؟»

## ۲. زبان بصری فعلی اپل: Liquid Glass
نکات کلیدی برای شبیه‌سازی با CSS خالص:

- عناصر کنترلی (دکمه‌ها، نوار ابزار، تب‌بار) به‌صورت یک **لایه شیشه‌ای شناور روی محتوا** ظاهر می‌شوند، نه چسبیده به پس‌زمینه صفحه.
- محتوا زیر این لایه‌ها اسکرول می‌شود؛ خود نوار ابزار ثابت (fixed/sticky) می‌ماند.
- تب‌بار پایین صفحه دیگر به لبه‌ها نچسبیده؛ به‌صورت یک **کپسول شناور با حاشیه از پایین و طرفین** (inset) نمایش داده می‌شود.
- سطح شیشه‌ای باید نور و رنگ محتوای زیرین را «شکست و انعکاس» دهد — با CSS این حس با ترکیب زیر شبیه‌سازی می‌شود:

```css
.liquid-glass {
  background: rgba(255, 255, 255, 0.55);
  backdrop-filter: blur(20px) saturate(180%);
  -webkit-backdrop-filter: blur(20px) saturate(180%);
  border: 1px solid rgba(255, 255, 255, 0.3);
  border-radius: 20px;
  box-shadow:
    0 8px 32px rgba(0, 0, 0, 0.08),
    inset 0 1px 0 rgba(255, 255, 255, 0.4);
}

/* حالت تیره */
@media (prefers-color-scheme: dark) {
  .liquid-glass {
    background: rgba(30, 30, 32, 0.55);
    border-color: rgba(255, 255, 255, 0.08);
  }
}
```

- این افکت فقط روی **لایه کنترلی** (نوار بالا/پایین، دکمه‌های شناور، شیت‌ها) اعمال می‌شود، نه روی کارت‌های محتوایی معمولی (که باید ساده و مات بمانند تا خوانایی حفظ شود).

## ۳. تایپوگرافی

فونت سیستمی  PeydaWeb است، پس عامل باید از این ترتیب fallback استفاده کند تا نزدیک‌ترین حس را روی هر سیستم‌عاملی بدهد:

```css
:root {
  --font-latin: -apple-system, BlinkMacSystemFont, "PeydaWeb", "segoe ui",
    system-ui, sans-serif;
  /* برای محتوای فارسی، فونتی با کیفیت و وزن‌های مشابه SF انتخاب شود */
  --font-fa: "PeydaWeb", "SF Pro Text", var(--font-latin);
}
body {
  font-family: var(--font-fa);
}
```

مقیاس تایپوگرافی مرجع اپل (Dynamic Type در اندازه پیش‌فرض)؛ این‌ها را به‌صورت متغیر CSS تعریف کن، نه عدد ثابت در هر جا:

| نقش (role) | اندازه | وزن | کاربرد در اپلیکیشن‌های اپل |
|---|---|---|---|
| Large Title | 34px | Regular/Bold | عنوان صفحه اصلی (Mail، Notes، Settings) |
| Title 1 | 28px | Bold | عنوان بخش بزرگ |
| Title 2 | 22px | Bold | زیرعنوان صفحه |
| Title 3 | 20px | Semibold | عنوان کارت/شیت |
| Headline | 17px | Semibold | عنوان ردیف در لیست |
| Body | 17px | Regular | متن اصلی — کف خوانایی |
| Callout | 16px | Regular | متن ثانویه برجسته |
| Subhead | 15px | Regular | زیرمتن ردیف |
| Footnote | 13px | Regular | توضیح کوچک |
| Caption 1 | 12px | Regular | برچسب زیر آیکون |
| Caption 2 | 11px | Regular | کوچک‌ترین متن سیستمی |

```css
:root {
  --text-large-title: 34px;
  --text-title1: 28px;
  --text-title2: 22px;
  --text-title3: 20px;
  --text-headline: 17px;
  --text-body: 17px;
  --text-callout: 16px;
  --text-subhead: 15px;
  --text-footnote: 13px;
  --text-caption1: 12px;
  --text-caption2: 11px;
}
```

**نکته مهم:** ۱۷ پیکسل کف خوانایی متن اصلی است — هرگز متن بدنه را کوچک‌تر از این مقدار طراحی نکن، مگر برای برچسب‌های فرعی.

## ۴. رنگ — سیستم معنایی، نه هگز ثابت

اپل رنگ را به‌صورت **نقش‌های معنایی سازگار با حالت روشن/تیره** تعریف می‌کند (systemBlue، label، secondaryLabel، systemBackground...) نه هگز ثابت. عامل هوش مصنوعی باید همین منطق را با CSS Custom Properties + `prefers-color-scheme` پیاده‌سازی کند:

```css
:root {
  /* رنگ‌های سیستمی (مقادیر تقریبی و رایج جامعه — اپل رسماً هگز ثابت منتشر نمی‌کند) */
  --color-blue: #007AFF;
  --color-green: #34C759;
  --color-red: #FF3B30;
  --color-orange: #FF9500;
  --color-yellow: #FFCC00;
  --color-purple: #AF52DE;
  --color-pink: #FF2D55;
  --color-teal: #5AC8FA;
  --color-indigo: #5856D6;

  /* نقش‌های معنایی — حالت روشن */
  --label: #000000;
  --label-secondary: rgba(60, 60, 67, 0.6);
  --label-tertiary: rgba(60, 60, 67, 0.3);
  --background: #FFFFFF;
  --background-grouped: #F2F2F7;
  --background-secondary: #FFFFFF;
  --separator: rgba(60, 60, 67, 0.29);
  --fill: rgba(120, 120, 128, 0.2);
}

@media (prefers-color-scheme: dark) {
  :root {
    --label: #FFFFFF;
    --label-secondary: rgba(235, 235, 245, 0.6);
    --label-tertiary: rgba(235, 235, 245, 0.3);
    --background: #000000;
    --background-grouped: #1C1C1E;
    --background-secondary: #2C2C2E;
    --separator: rgba(84, 84, 88, 0.6);
    --fill: rgba(120, 120, 128, 0.36);
  }
}
```

**قاعده الزامی برای عامل:** هیچ‌گاه هگز خام در استایل کامپوننت‌ها ننویس؛ همیشه از این متغیرهای نقش‌محور استفاده کن تا حالت تیره خودکار کار کند.

## ۵. فاصله‌گذاری، چیدمان و اندازه لمسی

- **شبکه ۸ واحدی** (با زیرواحد ۴): تمام فاصله‌ها مضربی از ۴ یا ۸ پیکسل باشند. این یک قرارداد رایج برای بازتولید خروجی اپل است (نه قانون رسمی منتشرشده، اما در عمل الگوی اپل را می‌سازد).
- **حداقل ناحیه لمسی: 44×44 پیکسل** برای هر عنصر تعاملی (دکمه، آیکون قابل لمس، ردیف لیست) — این قانون از زمان iPhone اول ثابت مانده و باید بدون استثنا رعایت شود.
- گوشه‌های گرد (border-radius) پیوسته و «هم‌مرکز» با فرم بیرونی هستند — کارت داخل یک ظرف گردتر، خودش شعاع کوچک‌تری دارد تا هارمونی حفظ شود.

```css
:root {
  --space-1: 4px;
  --space-2: 8px;
  --space-3: 12px;
  --space-4: 16px;
  --space-5: 24px;
  --space-6: 32px;

  --radius-sm: 10px;
  --radius-md: 14px;
  --radius-lg: 20px;
  --radius-full: 999px;

  --tap-min: 44px;
}
```

## ۶. الگوهای ناوبری و اجزا — استخراج‌شده از اپلیکیشن‌های خود اپل

عامل هوش مصنوعی باید بسته به نوع صفحه، الگوی متناظر را از این فهرست انتخاب کند (نه یک الگوی عمومی یکسان برای همه صفحات):

### ۶.۱ عنوان بزرگ + نوار ناوبری (Large Title Navigation)
مرجع: **Mail، Notes، Settings، App Store**
- عنوان صفحه در بالا بزرگ (34px) نمایش داده می‌شود و هنگام اسکرول به سمت پایین، کوچک و در نوار بالایی (Liquid Glass، ثابت) جمع می‌شود.
- دکمه‌های اقدام (مثل «ویرایش»، «+») در گوشه‌های همین نوار قرار می‌گیرند.

### ۶.۲ تب‌بار پایین (Bottom Tab Bar)
مرجع: **Music، App Store، Health، Files، Podcasts**
- کپسول شیشه‌ای شناور با فاصله از لبه‌های پایین/طرفین صفحه (inset)، نه چسبیده به کل عرض.
- حداکثر ۵ آیتم؛ آیکون + برچسب کوچک (Caption 1)؛ آیتم فعال با رنگ accent برجسته می‌شود.
- در برنامه‌های جستجومحور (Music)، آیتم جستجو معمولاً به‌صورت یک «جزیره» گرد جدا در سمت مقابل تب‌بار اصلی قرار می‌گیرد.

### ۶.۳ لیست‌های گروه‌بندی‌شده تو‌رفته (Inset Grouped List)
مرجع: **Settings، Reminders، Health (بخش تنظیمات)**
- ردیف‌ها داخل کارت‌های سفید/خاکستری‌روشن با گوشه گرد قرار می‌گیرند، با فاصله از لبه صفحه.
- هر گروه از ردیف‌ها یک عنوان کوچک خاکستری (Footnote، حروف بزرگ در انگلیسی) بالای خود دارد.
- بین ردیف‌ها یک خط جداکننده نازک (`--separator`) با تورفتگی هم‌تراز با متن، نه از لبه تا لبه.

### ۶.۴ کنترل بخش‌بندی‌شده (Segmented Control)
مرجع: **Health (روز/هفته/ماه/سال)، Podcasts، Maps**
- چند گزینه هم‌عرض داخل یک کپسول خاکستری‌روشن؛ گزینه انتخاب‌شده پس‌زمینه سفید با سایه ملایم می‌گیرد و با ترنزیشن نرم جابه‌جا می‌شود.

### ۶.۵ شیت (Sheet / Modal نیمه‌صفحه)
مرجع: **Calendar (افزودن رویداد)، Reminders (افزودن یادآور)، Mail (نوشتن ایمیل)**
- از پایین صفحه با انیمیشن spring بالا می‌آید، گوشه‌های بالایی گرد بزرگ (۲۰px+)، یک «دستگیره» کوچک خاکستری بالای شیت.
- پس‌زمینه صفحه اصلی کمی تیره/بلور می‌شود تا تمرکز روی شیت باشد.

### ۶.۶ نوار جستجو (Search Bar)
مرجع: **Mail، Notes، Music، Contacts**
- کپسول با پس‌زمینه `--fill`، آیکون ذره‌بین در ابتدا (در RTL: سمت راست ورودی — نه لزوماً لبه راست کامل صفحه).
- هنگام فعال شدن، معمولاً کمی پایین‌تر و به‌صورت اورلی روی محتوا ظاهر می‌شود.

### ۶.۷ اکشن‌های کشویی روی ردیف (Swipe Actions)
مرجع: **Mail (آرشیو/حذف)، Reminders (تکمیل)، Notes (پین/حذف)**
- کشیدن ردیف به چپ/راست، دکمه‌های رنگی (قرمز برای حذف، سبز/آبی برای اکشن‌های مثبت) را آشکار می‌کند.
- در نسخه فارسی/RTL جهت کشیدن باید **معکوس** شود (کشیدن به راست برای حذف، چون جریان خواندن از راست به چپ است).

### ۶.۸ کارت‌های داشبورد (Content Cards)
مرجع: **Health (خلاصه سلامت)، Weather (کارت‌های آب‌وهوا)، Wallet**
- کارت‌های مستقل با پس‌زمینه ساده (نه شیشه‌ای)، گوشه ۱۴–۲۰px، سایه بسیار ملایم، عنوان کوچک بالای هر کارت.
- این‌جا افکت Liquid Glass اعمال **نمی‌شود** چون این لایه محتوا است نه لایه کنترلی (طبق اصل Deference).

## ۷. دسترس‌پذیری (اجباری)

- کنتراست متن/پس‌زمینه حداقل مطابق WCAG AA.
- تمام عناصر تعاملی باید `:focus-visible` با outline قابل مشاهده داشته باشند (شیشه‌ای بودن نباید فوکوس کیبورد را محو کند).
- انیمیشن‌ها باید به `prefers-reduced-motion` احترام بگذارند:

```css
@media (prefers-reduced-motion: reduce) {
  * { animation-duration: 0.01ms !important; transition-duration: 0.01ms !important; }
}
```

## ۸. الزامات خاص راست‌چین و فارسی (RTL)

چون مخاطب این اپلیکیشن‌ها عمدتاً فارسی‌زبان است، عامل باید موارد زیر را رعایت کند:

1. `<html dir="rtl" lang="fa">` در ریشه سند.
2. استفاده از خواص منطقی CSS به‌جای جهت‌دار: `margin-inline-start` به‌جای `margin-left`، `padding-inline-end` به‌جای `padding-right`، `inset-inline-start` به‌جای `left`.
3. آیکون‌های جهت‌دار (فلش بازگشت، chevron ناوبری، آیکون ارسال) باید در RTL آینه (`transform: scaleX(-1)`) شوند؛ آیکون‌های خنثی (قلب، ستاره، زنگ) آینه نمی‌شوند.
4. جهت اسلاید شیت‌ها و ترنزیشن صفحه (push/pop ناوبری) در RTL معکوس می‌شود؛ ورود صفحه جدید از **چپ** اتفاق می‌افتد، نه راست.
5. اعداد: بسته به تصمیم پروژه، از ارقام فارسی یا لاتین به‌صورت یکدست استفاده شود؛ در تاریخ/زمان و اعداد مالی معمولاً ارقام لاتین با جهت LTR داخل یک `<span dir="ltr">` قرار می‌گیرند تا ترتیب رقم‌ها به‌هم نریزد.
6. فونت فارسی انتخابی باید وزن‌های متعدد (Regular/Medium/Semibold/Bold) داشته باشد تا بتوان سلسله‌مراتب تایپوگرافی بخش ۳ را دقیقاً بازتولید کرد.

## ۹. دستورالعمل مستقیم (Prompt Contract)

هنگام تولید هر صفحه یا کامپوننت جدید، این چک‌لیست را رعایت کن:

- [ ] فقط از HTML + CSS خالص استفاده کن (استفاده از فریم ورک bootstrap مجاز است).
- [ ] تمام رنگ‌ها از متغیرهای نقش‌محور بخش ۴ بیایند؛ هیچ هگز خامی داخل کامپوننت درج نشود.
- [ ] تمام اندازه فونت از مقیاس بخش ۳ بیاید.
- [ ] تمام فاصله‌ها مضرب ۴ باشند.
- [ ] هر عنصر لمسی حداقل 44×44px باشد.
- [ ] پیش از افزودن `backdrop-filter`، بررسی کن که این عنصر واقعاً «لایه کنترلی» است (نوار بالا/پایین، شیت، دکمه شناور) نه یک کارت محتوایی ساده.
- [ ] برای هر صفحه، تصمیم بگیر کدام الگوی ناوبری بخش ۶ متناسب است و همان را با وفاداری کامل پیاده کن، نه یک ترکیب دلبخواهی.
- [ ] `dir="rtl"` و خواص منطقی CSS رعایت شود؛ آیکون‌های جهت‌دار آینه شوند.
- [ ] حالت تیره از طریق `prefers-color-scheme` به‌صورت خودکار پشتیبانی شود، نه یک تم جدا که فراموش می‌شود.
- [ ] `prefers-reduced-motion` و `:focus-visible` رعایت شود.
- [ ] از افزودن فریم‌ورک CSS (Bootstrap/Tailwind و…) یا آیکون کپی‌شده از اپل خودداری کن؛ آیکون‌ها باید SVG خطی سفارشی هم‌وزن با فونت باشند (شبیه منطق SF Symbols: خطوط باریک، هم‌تراز نوری با متن).
